# Cofertility fork

Branches:

- `main`: mirror of `upstream/main`. Never commit here.
- `feat/<name>`: one feature per branch, based on `upstream/main`, each opened as a PR to twentyhq/twenty.
- `cofertility/infra`: fork-only changes that will never go upstream (image workflow, this folder). Based on `upstream/main`.
- `cofertility/v<version>`: release branch, generated by `release.sh`. Never develop on it.

## Starting a feature

```bash
git fetch upstream
git switch -c feat/<name> upstream/main --no-track
```

Add it to `release-branches` on `cofertility/infra` to ship it in the next release. Keep it current with `git rebase upstream/main`, not merges: the release script replays each branch's own commits onto the upstream tag and skips merge commits.

## Cutting a release

One-time setup:

```bash
git config rerere.enabled true
git config alias.cofertility-release '!f() { git show cofertility/infra:cofertility/release.sh | bash -s -- "$@"; }; f'
```

Then:

```bash
git cofertility-release latest            # latest published upstream release
git cofertility-release 2.52.0            # twenty/v2.52.0 + cofertility/infra + release-branches
git cofertility-release 2.52.0 --rebuild  # recreate after updating a feature branch
```

The script reads `release-branches` and itself from `cofertility/infra`, so it works from any checkout. The full flow, through image build and deploy, is the `cutting-cofertility-release` skill in `.claude/skills/`.
